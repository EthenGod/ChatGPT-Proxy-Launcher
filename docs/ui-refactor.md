# 配置器界面重构

## 目标与阶段

在 `refactor/ui` 分支使用 React、TypeScript 和 Tauri 2 重建配置器。Rust 连接现有 C++ 核心。保留单 EXE、后台命令和独立启动器。每阶段完成后汇报，等待用户确认。不自动提交、合并或发布。

1. 技术骨架。验证单文件、只读加载、静态链接和后台兼容。
2. 界面原型。模拟接口承载完整设置、三语、主题和交互。
3. 功能接入。复用原有保存、回滚和系统操作。
4. 交付收尾。切换默认入口，完成回归、性能对照和本地测试包。

第 1 阶段和原生兼容补充已完成。第 2 阶段已实现完整交互原型，等待用户确认视觉方向，再进入第 3 阶段。默认 `build.cmd` 仍构建原生配置器。普通 Tauri 构建保留只读入口；独立原型入口使用内存模拟数据，不执行部署、联网检测或系统设置操作。

第 2 阶段采用单页设置布局，共用按钮、开关、菜单、折叠区和弹窗。原型与桌面接口分开，业务交互统一通过有类型的接口。预览参数校验仅用于模拟交互，不能替代第 3 阶段的 C++ 校验。验收覆盖状态变化、检测竞争、关闭保护、键盘焦点、三语、短窗口、深浅色和无障碍设置。

## 分层与边界

- `frontend/src/features/setup/` 包含设置页面、服务接口和原型参数预览。`components/` 提供 Base UI 控件，`styles/` 提供 Radix 语义颜色与动效，`i18n/` 继续读取根目录的三语词条。
- `frontend/src/platform/mock.ts` 提供内存模拟接口。`prototype.tsx` 是独立原型入口，`platform/prototype-window.ts` 只连接窗口就绪、关闭和关闭请求事件。原型不调用真实配置加载或保存接口。
- `frontend/src-tauri/` 包含窗口、原生命令、Rust 数据类型和 C ABI 包装。只有主窗口可以调用明确授权的三项命令；另授予事件监听与取消监听权限。不开放文件系统、Shell 或任意命令调用权限。
- `src/SetupBridge.*` 将现有加载结果转换为有界 UTF-8 JSON。C++ 分配结果，Rust 作用域对象调用 C++ 释放。异常不跨越 ABI。只读失败始终报告尚未提交。
- 现有部署核心与启动器不迁移。后台命令在 WebView2 检查和 Tauri 初始化之前分流。原始 UTF-16 参数不重新编码或拼接。
- 新 EXE 静态链接 C++ 核心、原生兼容界面和 Visual C++ 运行库。Tauri 生成图标和版本资源；额外资源放同次构建的启动器和界面能力信息，避免重复 manifest 或版本资源。
- `test-harness` 仅用于独立测试产物。它要求显式测试目录，隔离全部快捷方式、部署文件、`.env` 和 WebView 数据。测试观测文件只存在于该构建。普通产物不读取测试环境变量。
- `ui-prototype` 强制依赖 `test-harness`，不能用于正式交付。窗口关闭请求先交给页面：保存期间忽略，未保存时确认，确认后才由受限命令关闭。原型的目录与程序选择使用样例列表；原生文件选择器留到第 3 阶段接入。

## 构建与检查

### 原生兼容模式

- 同一个 EXE 支持 `--compatibility`。必须单独使用，不能混入后台参数。入口在 WebView2 检查和 Tauri 初始化前分流。
- 旧界面增加兼容模式标题与版本标识，三语使用相同布局测量。保存、回滚、代理、附加程序、主题和语言偏好继续复用原实现。
- PowerShell 在校验 EXE 后只读加载资源 102。没有该资源的旧配置器直接打开，不安装 WebView2，也不传入新参数。
- 新配置器按微软文档读取用户和机器的运行库版本。缺少运行库时显示安装（推荐）、兼容界面和取消。直接双击 EXE 则自动回退兼容界面。
- 选择安装后才下载微软 Evergreen Bootstrapper。执行前校验 Authenticode 状态和微软发布者，执行 `/silent /install`，结束后重新检查运行库。下载、签名、安装或检测失败时停止，不误报新界面可用。
- 取消不打开配置器或项目网页，清理本次下载后返回 PowerShell。后台命令不检查运行库，也不询问安装。
- 风险是下载安装依赖网络与本机策略。保留不联网的兼容入口。原生模式不创建 WebView 子进程，沿用原生界面的内存和线程生命周期。

### 开发命令

需要 Node.js 24.10 以上、Rust 1.99 以上的 MSVC 工具链、Clippy、rustfmt、Visual Studio C++ 工具和 Windows SDK。前端依赖使用锁文件。缓存和产物放在 `work/`，不改系统 PATH。

先在 `frontend` 运行 `npm ci`，然后在根目录运行：

```powershell
.\frontend\desktop.ps1 -Command build
.\frontend\desktop.ps1 -Command test
.\frontend\desktop.ps1 -Command harness
cmd /c tests\test-bridge.cmd
.\tests\ui-stage1-tests.ps1
```

若 Cargo 不在 PATH，可用 `-RustBin` 指定现有 MSVC 工具链的 `bin` 目录，或设置进程变量 `CHATGPT_RUST_BIN`。脚本结束后恢复环境变量。

第 2 阶段桌面预览在根目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\frontend\desktop.ps1 -Command prototype
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\frontend\preview.ps1
```

已有测试包时只运行第二条。在 `frontend` 目录中，把脚本路径改成 `.\preview.ps1`。`-ExecutionPolicy Bypass` 只作用于这次 PowerShell 进程，不修改系统或用户的执行策略。

预览脚本创建独立会话目录，再启动 `work/ui-prototype/ChatGPTLauncherSetup.exe`。不要单独双击该测试 EXE。所有设置、主题和语言更改仅保存在当前原型内存中。顶部状态菜单可切换首次部署、缺失或未知版本、保留的静默值、长路径、加载失败、保存过程、不同失败结果和保存后续操作。切换状态会重置本次演示输入。静默选项继续禁用。

浏览器预览可在 `frontend` 运行 `npm run dev`，访问 `http://127.0.0.1:5174/prototype.html`。它只验收页面交互，不能替代桌面壳验证。交互回归在 `tests/frontend/interaction.test.tsx`；桌面生命周期检查在根目录运行：

```powershell
.\tests\ui-prototype-tests.ps1
```

该检查默认观察 60 秒，并正常开关窗口三次。关闭测试使用与标题栏相同的系统命令，并核对事件计数。`-Action Start -RemoteDebugging` 只对本次隔离测试进程启用本地调试端口。普通预览不启用此端口。测试进程和子进程按 PID、启动时间与程序路径核对，不能关闭其他 WebView 进程。

普通测试包位于 `work/ui-stage1/`。隔离测试包位于 `work/ui-stage1-test/`。两者都不是已发布版本，不覆盖当前用户部署。测试源码位于 `tests/`。

桌面构建每次使用新的 `work/ui-assets/` 子目录。不会混入旧资源，也不自动删除旧文件。`work/ui-stage1-build.json` 与 `work/ui-stage1-test-build.json` 记录该次 EXE 和内嵌启动器的哈希。不要把这些本机记录加入源码包。

界面测试需要正常桌面会话。受限沙箱中的 WebView2 可能无法初始化，进程树查询也可能被拒绝。旧 GUI 的隔离基线可运行 `work/setup-ui-tests.exe <项目 work 目录> --benchmark`；它只使用测试路径和系统操作替身。

## 风险与验收

- WebView2 会增加界面的启动和内存开销。记录整个界面进程树，而非只统计主 EXE。启动器热路径不得引入此依赖。
- 后台命令继续使用原结果文件、退出码和锁。测试对照原生入口与新 EXE 的隔离结果，禁止真实自启和应用退出操作。
- 页面显示成功不代表只读接口成功。测试同时核对原生命令完成记录和页面就绪记录。
- 第 1 阶段不验收保存、自启、联网和退出 ChatGPT。界面样式仍是技术预览。

本机初步测量如下。它们用于确定后续优化方向，不代表所有机器。原生数据来自使用系统操作替身的屏幕外测试窗口；Tauri 数据来自可见窗口和全新隔离 WebView 目录。两种启动标记不同，不作为严格的冷启动排名。

## 第 2 阶段界面细化

- 合并代理标题与开关，关闭时平滑收起输入。精简启动选项、版本和高级区域文案；目录选择放入输入框。语言和主题使用带可访问名称的图标按钮。保存成功后只显示“完成”，保留保存结果、错误原因和退出 ChatGPT 的提醒。
- 常规按钮和输入框统一高 36px；控件、卡片、弹窗圆角统一为 8/12/16px。菜单和分段选项按外框、边框、内边距计算内侧圆角。字号保持 24/14/12px。颜色继续按 [Radix 色阶用途](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale) 分配；主按钮文字在当前浏览器中的对比度约为浅色 4.77:1、深色 8.98:1。
- 高频操作使用 150ms 过渡；弹层进入 250ms，退出 200ms。轻微回弹只用于空间变化，颜色和透明度使用普通缓动。折叠高度使用无回弹缓动。开启减少动态效果后停用动画。空闲页面无持续动画。
- 弹窗正文可滚动，底部操作保持可见。选择列表为勾选图标保留宽度。关闭后恢复触发按钮焦点；保存后焦点落在“完成”。
- TypeScript 和 18 项前端检查通过。三语、两种主题在 640×760、480×400、320×400 浏览器视口中没有横向溢出，底部按钮可见。另检查 320×280 的长弹窗、高对比度、减少动态效果和动画时长。浏览器模拟 100%、150%、200% 像素比例后，按钮与输入框仍等高。新测试覆盖代理收起后保留输入，以及用空格重新展开。
- 最终桌面包构建通过，约 8.81 MiB。隔离测试完成三次原生关闭，每次所属进程均退出，没有部署写入。另在实际窗口中检查未保存关闭确认、Esc 返回、保存后的单个“完成”按钮和回车退出；桌面页面无控制台错误。本次三轮各观察 2 秒，页面就绪约 684–1320 ms，进程树私有内存约 194.9–198.2 MiB。这是关闭回归的短时样本；没有重新进行 60 秒空闲或长期性能验收。
