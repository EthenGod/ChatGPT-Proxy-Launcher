# 图形部署工具

## 目标

提供单文件 `ChatGPTLauncherSetup.exe`，内嵌同次构建的启动器。用户选择启动参数后，部署启动器并保存当前用户的登录自启快捷方式。高级选项允许选择部署目录，主界面和二级设置页均提供可复制的实时参数预览。

## 方案

- 原生 C++ / Win32，静态运行库。界面、参数处理、文件部署和 Shell 快捷方式操作分离；现有启动器行为保持不变。
- 默认目录为 `%LOCALAPPDATA%\ChatGPTProxyLauncher`；自启目录通过 Known Folder API 查询，不拼接用户名或系统目录。
- 在默认目录保存 `Launcher settings.lnk` 作为配置记录，记录实际部署目标和完整参数。即使关闭自启也能恢复设置；实际自启状态以启动目录中的快捷方式为准。
- 快捷方式用 `IShellLinkW` / `IPersistFile` 读写，目标、参数、工作目录分开保存。未知参数保留原文，常用参数由界面生成；拒绝重复受管选项和诊断专用参数。
- 替换前保存旧文件内容，使用同目录临时文件和重命名保存，回读校验。失败时恢复本次已修改的明确文件，恢复失败必须告知用户。目录迁移后保留旧目录文件，不批量清理。
- 不覆盖不属于本工具的同名快捷方式或未知 EXE；不自动启动 ChatGPT、不提权、不常驻、不写日志。
- 界面参考 Apple 的层级、留白和分组，统一自绘开关、按钮、协议分段、输入框外框和滚动条；保留 Windows 文本输入、复选框及单选的键盘行为。高级入口固定在左下角，打开二级设置页，不拉长主界面。
- 布局使用批量窗口定位；滚动只批量平移内容，不重建布局。父子控件缓冲绘制，移动后一次立即重绘，处理滚轮及拖动；参数预览滚至边缘时可继续滚动页面。
- 操作按钮使用 `BS_OWNERDRAW`，同步 `WM_DRAWITEM` 与普通绘制共用缓冲绘制入口；对话框导航改变默认按钮时保留自绘样式，避免原生矩形先出现一帧。开关和单选保留原生状态模型。底部状态行自绘并按文字高度居中，按钮等高、左右与内容对齐；高级入口使用浅底圆角、独立绘制箭头和仅键盘焦点可见的圆角描边。
- 首次加载且没有保存记录时，默认勾选登录自启；静默选项保留原有默认勾选值，但标记“暂不可用”并置灰。恢复设置时保留原值和对应参数，编辑、保存成功或失败后都不解锁，Tab 跳过该控件。保留参数不代表静默启动可用。
- 只有勾选自启且部署保存成功，才调用 `StartupIntegration` 尝试关闭已准确识别的当前用户 Run 项。同一次打开工具期间只尝试和提醒一次；先提示“部署已完成”，关闭提示后再打开 `ms-settings:startupapps`。检查失败不把成功的部署误报为失败；未保存或保存失败不触发系统操作。成功且无新更改时显示“已保存”和“完成”，避免反复部署。
- 读取已验证包内的 `AppxManifest.xml`，使用系统 XmlLite 解析器提取指向 `app/ChatGPT.exe` 的商店自启扩展下的 `TaskId`；禁止 DTD，限定命名空间、父子关系及标识字符，不按显示名称猜测。读取已有当前用户 `SystemAppData/<包家族>/<TaskId>/State`：0/1/3 已关闭，不写入；2 尝试改为 1 并回读；4 是策略启用，保留；未知类型/值、缺失记录均不创建或修改。只写 State，不改 UserEnabledStartupOnce。写前留存原值，回读失败时尝试恢复并回读恢复结果；若读到其他状态，避免覆盖并发修改。
- 清单声明不等于实时开关状态，忽略 `Enabled` 对当前状态的暗示。传统 Run 键不存在或没有匹配项属于没有可处理条目，不作为自动关闭失败。商店处理复用同一 `StartupIntegration`，仍只在正常保存成功且用户勾选自启时尝试一次。

## 风险与边界

- 端口检测由独立 `ProxyDetection` 模块只读执行，界面在空端口框点击或键盘焦点进入时启动后台线程。已有值不覆盖；检测期间的编辑、恢复配置和保存使旧结果失效。失败与多结果提示显示在底部，不弹窗打断输入。
- 仅支持 127.0.0.1 / localhost 的 HTTP、SOCKS5：从 `%APPDATA%` 下 Clash Verge Rev 的 `io.github.clash-verge-rev.clash-verge-rev/clash-verge.yaml`、FlClash 的 `com.follow/clash/config.yaml` 或 `com.follow/flclash/config.yaml` 提取简单顶层端口字段（混合优先），同时核对对应内核进程的 IPv4 监听。HTTP 可参考启用的 Windows 系统代理。来源端口冲突不猜选；控制器、节点端口、关闭的系统代理、HTTPS 目标映射不当作候选。
- 配置位置参考 [Clash Verge Rev 源码](https://github.com/clash-verge-rev/clash-verge-rev/blob/dev/src-tauri/src/utils/dirs.rs)、[FlClash 路径源码](https://github.com/chen08209/FlClash/blob/main/lib/common/path.dart)及 [Windows 应用元数据](https://github.com/chen08209/FlClash/blob/main/windows/runner/Runner.rc)。这些不是稳定的跨产品接口；非标准安装、IPv6、复杂 YAML 或配置格式变化会回退手填。最多读取 4 MiB 的单个运行配置，不输出节点或订阅内容、不写检测日志、不访问控制 API。
- 扩大兼容范围：CFW 读取用户 `.config/clash/config.yaml`，或运行中 GUI 旁的 `data/config.yaml`，便携路径还核对内核位于同一程序目录；目录约定可参照 [CFW 更新工具实现](https://github.com/Jrohy/cfw-updater/blob/master/data.go)。v2rayN 从运行内核路径识别新旧程序根目录，要求存在 `v2rayN.exe`；本地应用数据目录下的内核要求 v2rayN GUI 正在运行。仅读取根目录或本地应用数据目录的固定运行配置，不遍历磁盘，不读取节点数据库或进程命令行。
- v2rayN 路径依据 [Utils](https://github.com/2dust/v2rayN/blob/master/v2rayN/ServiceLib/Common/Utils.cs) 和 [Global](https://github.com/2dust/v2rayN/blob/master/v2rayN/ServiceLib/Global.cs)。用 Windows 自带 JSON 解析器读取 `inbounds`，最多 256 项，匹配 `protocol/port` 或 `type/listen_port`，再核对同一内核 PID 的监听。存在现代配置时不回退到旧配置。JSON 认证、TLS/自定义传输、非本机绑定和异常字段回退手填。保留原有轻量原生架构，无额外运行时安装。
- [Xray 文档](https://xtls.github.io/config/inbounds/socks.html)声明 SOCKS 入站兼容 HTTP；独立 HTTP 入站优先，否则按该行为使用 Xray SOCKS 端口，不能据此推断旧版 V2Ray。sing-box 根据显式 [mixed 入站](https://sing-box.sagernet.org/configuration/inbound/mixed/)识别。旧内核、被修改的内核或配置更改尚未生效时，仍须在代理工具内核对；监听存在不证明协议握手或联网成功。

- 多文件更新不是跨文件系统事务；进程被强制终止或断电时不能承诺整体回滚。若留下不匹配的快捷方式，需要先手动处理冲突文件，再重新运行工具保存。
- 自定义目录可能无写入权限或文件被占用，界面展示具体错误；不自动请求管理员权限。
- 代理和静默参数由 ChatGPT 解释，保存成功不等于登录自启、隐藏窗口或联网成功。
- 配置和快捷方式包含用户路径及参数，不纳入版本控制。
- 自动关闭只针对 Windows 包接口验证的本项目目标包及其中实际存在的 `app\ChatGPT.exe`，包括匹配的 Run 项与清单中的商店任务。商店状态记录属于兼容处理，不是 ChatGPT 专用 API；Windows 版本变化可能导致无法处理。不改 HKLM、组策略，不猜测缺失或未知状态；失败时引导手动核对。取消本工具自启不重新启用应用原自启。
- Run 禁用标记参考 [Electron 的实现](https://github.com/electron/electron/blob/main/shell/browser/browser_win.cc)。商店 [StartupTask API](https://learn.microsoft.com/en-us/uwp/api/windows.applicationmodel.startuptask) 限于应用自身包；[Windows 设置 URI](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-settings) 用于引导核对。这些状态可能随 Windows 或应用更新改变，界面不承诺关闭所有机制。
- MSIX 状态路径及 0–4 的含义参考 [微软 Teams MSIX 自启文档](https://learn.microsoft.com/en-us/microsoftteams/teams-client-vdi-requirements-deploy#teams-autostart)。将这一状态模型用于清单验证后的 ChatGPT 任务属于兼容推断，不代表微软提供跨应用 StartupTask 管理 API。保留只操作已有 DWORD、策略保护及人工核对入口。

## 附加程序

- 目标：用户通过本工具启动 ChatGPT 后，可以一起打开插件。高级页提供“添加程序”和“打开启动目录”。添加只写快捷方式，同名不同目标不会覆盖。
- 方案：成功创建 ChatGPT 进程后只查看专用目录第一层。没有该目录就退出。按需初始化 COM，复用读取快捷方式的缓冲区。直接启动本机 EXE，保留快捷方式参数和工作目录。不监视进程，不等待窗口。
- 边界：检查模式和 ChatGPT 启动失败时不运行。坏条目不影响其他程序。子进程继承防止再次派发的标记。目录不保证执行顺序；重复启动 ChatGPT 也会再次请求打开插件，不保证插件单实例或已与 ChatGPT 连接。
- 验证：用隔离目录、真实 Shell 快捷方式及测试子进程验证参数、工作目录、同名保护、坏条目、非递归枚举和递归保护。计时区分目录检查与真实程序启动，未验证第三方插件兼容性。

## 桌面快捷方式

- 在主界面的启动设置中提供开关，默认关闭。用户在保存前选择，不额外弹窗。
- 用 `FOLDERID_Desktop` 获取当前桌面，支持系统重定向的桌面位置。快捷方式使用当前参数、工作目录和启动器图标。
- 以桌面快捷方式的实际状态恢复开关。只管理标记和目标均匹配的文件。关闭后保存会移除此文件。
- 桌面文件与程序、配置、自启文件一起保存。操作失败时撤销本次文件更改。同名文件冲突时保留原文件，并沿用打开目录的提示。
- 不增加常驻进程或后台扫描。保存时只额外处理一个指定文件。
- 隔离测试覆盖默认关闭、创建、参数与目录同步、移除、冲突保护及保存失败回滚。界面测试检查开关保存和恢复。实际桌面双击启动与重定向桌面的端到端行为仍需用户验证。

## 界面规范

- 保留原生 Win32 和已有功能。首页按启动设置、代理连接、参数预览分组。高级页保留目录和额外参数。移除重复副标题和参数框说明，不新增确认弹窗。
- 字号固定为 24、14、12 个逻辑像素。标题和分组用字重区分。外边距 32，卡片内边距 16。卡片圆角 16，输入框和按钮圆角 10，协议分段内圆角 6。
- 使用 [Radix 色阶规则](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)。Gray 1/2 用于背景，3/4 用于控件和悬停，6/7 用于边框，11/12 用于文字。Blue 用于选中和主要操作。浅色主按钮用 Blue 11 配白字，深色用 Blue 9 配深色文字。
- 开关位移和悬停颜色过渡为 150 毫秒。过渡从当前显示值开始，支持中途反向。按压立即反馈。Windows 关闭客户端动画或启用高对比度时直接切换。
- 计时器只在过渡期间工作。只重绘相关控件，不在动画中重新布局，不新增线程、依赖或常驻进程。
- 保留 `BS_OWNERDRAW`、`WM_DRAWITEM` 和原有键盘行为。验证浅色、深色、高对比度、窄窗口、100% 至 200% 缩放、滚动及保存流程。测试不修改真实配置。
- 右上角提供 36×36 逻辑像素的圆角方形外观按钮，圆角为 10。深色时显示太阳，浅色时显示月亮，图案表示切换目标。图案使用矢量描边，保留无障碍名称和键盘焦点环。默认深色，选择独立保存。高对比度优先。切换外观不改变启动参数或待保存状态。
- 协议选择采用自绘底块和单层边框，鼠标选择不叠加焦点框，键盘操作保留焦点环。方向键循环切换，空格选中，Tab 只停在当前项。选中状态由界面统一管理，避免原生单选绘制插入。
- 外观与协议测试覆盖偏好缺失、无效值、写入失败、主题刷新、三种模式下连续选择、键盘操作和绘制像素。偏好读写使用测试替身。
- 风险：绘制测试不能替代真实显示器上的视觉体验。跨显示器缩放和触控仍需实际使用验证。

## 验证计划

- 构建原启动器和配置工具，验证嵌入资源与启动器产物一致。
- 隔离测试覆盖参数往返、中文、引号、空参数、长度限制、错误返回、部署迁移、保留未知文件、快捷方式开关及回滚。
- 检查实际窗口的布局、实时预览、高级选项、键盘与缩放。
- 更新 README 并核对 Git 忽略规则；不修改本机正在使用的启动器和自启设置。

## 回归验证范围

根目录运行 `cmd /c tests\test-build.cmd`，先构建正式程序，再运行六组隔离测试。以当次结果为准，不将历史通过记录当作当前保证。

- 启动器：包筛选、有限重查、参数边界、随机参数、内存与句柄释放，以及实际测试子进程的参数传递。
- 部署：参数往返、中文和引号、路径校验、内嵌资源一致性、快捷方式读写、目录迁移、未知文件保护及故障回滚。
- 自启：模拟注册表和清单，覆盖目标筛选、已有状态、策略保护、缺失或未知记录、权限失败、回读及恢复；不修改真实自启配置。
- 代理：合成配置、进程和监听信息，覆盖端口范围、JSON 入站 256/257 项边界、身份与协议筛选、认证/传输排除、多个结果和异常配置；不读取真实代理配置。
- 界面：隔离部署、默认选项、实时预览、异步检测和保存、页面切换、滚动、浅深色及缩放；操作按钮采用 `BS_OWNERDRAW` / `WM_DRAWITEM`，验证默认样式、Tab、回车和空格行为。
- 任务栏：隔离快捷方式验证身份边界、备份、原子替换、重复调用和失败处理，Shell 通知替换为测试桩。

测试不启动 ChatGPT，不打开真实系统设置；渲染图、快捷方式和其他测试产物保留在 Git 忽略的 `work/`，由用户手动清理。需要静态分析时可另用 MSVC `/analyze`；它不代替测试。

真实桌面交互、多显示器 DPI、高对比度系统主题、不同版本应用的自启关闭、实际登录、静默启动、商店更新和联网仍需使用时验证。
