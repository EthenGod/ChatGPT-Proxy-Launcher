# 可维护性与逻辑审查

## 目标与范围

2026-11-12，以提交 `671b3ca` 为基线。

- 将启动参数解析、`.env` 文本合并和部署文件操作分开，避免修改文本规则时误碰文件提交与回滚。
- 将界面的开始保存、完成保存和自启提醒拆成独立函数。窗口消息入口只负责分发。
- 检查成功与失败后的界面状态、异常输入、文件所有权、回滚及资源释放。
- 保持原有外观、启动参数语义、轻量启动方式和旧 Release。测试不操作真实自启、代理配置或 ChatGPT。

## 验收方法

- 对具体问题先增加可复现的隔离测试，再修改实现。
- 参数和 `.env` 测试通过公开函数检查结果，避免依赖源码内部的临时结构。
- 完整构建与隔离测试通过；静态分析覆盖所有正式 C++ 源文件。
- 检查新增模块是否进入构建、测试和发布源码清单。同步更新模块路径和交接约定。

## 边界

拆分不新增第三方依赖，也不把系统操作移到启动器热路径。隔离测试不能证明真实网络、自启或第三方应用退出成功。

## 逻辑检查结果

发现并复现一处键盘操作问题：保存成功后，“保存”按钮已经禁用，代码仍尝试将焦点放到它上面。现在成功后聚焦“完成”，失败后回到“保存”。回归测试先在旧逻辑上失败，再在修复后通过；同时确认按回车可以关闭已完成的配置。

其余重点检查如下，未发现新的可复现阻塞问题：

- 参数中的空值、中文、引号、未知选项、重复选项、`--` 分隔符和长度限制。
- `.env` 中其他配置、注释、BOM、多行内容和重复代理变量的处理，以及失败时输出不变。
- 同名文件所有权、首次部署期间的冲突、快捷方式回读、迁移和保存失败回滚。
- 保存前不操作系统设置；保存失败不请求应用退出；自启提醒和偏好保存失败不覆盖已经完成的部署结果。
- 启动器继续保留显式程序路径、原样参数传递、有限包查询和启动后退出。实际应用退出仍依赖应用自身的退出命令。
