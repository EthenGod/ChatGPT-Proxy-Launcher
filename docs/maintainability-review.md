# 可维护性与逻辑审查

## 配置器分支与全项目维护

本轮基线为 `ce73b5c`。重点是设置页、原生连接层、两种配置器和独立启动器共用的构建流程。

- 设置页用同一处状态管理保存、文件选择和关闭。参数校验单独管理，只有对应当前输入的成功结果可以启用保存。窗口切换主题时，须等上一轮的标题栏和背景操作都结束。
- 原生命令在 Rust 中使用具名枚举。编号沿用 `SetupBridge.h`，由 Rust 契约测试对照。保存完成后先填入独立的提交状态，再分配返回数据。无法识别的提交状态按结果待确认处理。
- 启动器、部署发现、快捷方式和原生选择器使用 Windows SDK 的 `ComPtr` 管理 COM 引用。各入口保留原有 COM 初始化时机。MSVC 公共编译参数集中在 `tools/msvc-common.rsp`。
- 发布、交付检查和文档检查共用 `tools/release-sources.ps1`。构建前记录各文件哈希，生成源码 ZIP 后逐项核对完整路径及内容。运行 `release.cmd -TestPackage` 可在隔离目录复测整个流程。

### 修复与整理

- 修复删除快捷方式时的并发缺口。旧链接原来在复查后按路径删除；关闭自启或桌面入口时也可能删除期间被外部修改的文件。现在持有同一文件句柄，核对内容后再标记删除。写入、替换被拒绝时停止保存并回滚。
- 修复恢复已删除的当前快捷方式时覆盖外部新文件的问题。新旧链接都只恢复到空缺路径；出现新文件时保留它，并报告回滚不完整。新增四个隔离场景，先复现旧行为，再验证修复。
- 删除重复的注册项核对与删除实现，统一使用 4 KiB 缓冲区逐段比较。独立测试覆盖内容和长度不符、文件占用、读取不完整、删除失败、并发写入与重命名、空文件和句柄释放。
- 链式上下文改为移动局部 JSON 对象，参数数组预留容量，减少同一字段的反复查找。上下文树和序列化结果在创建子进程前释放，避免占用整个等待期间的内存。同步删除未使用的头文件和旧测试替身。
- 中文、英文、日文共用适用于新旧链接的冲突提示。模块说明、交接约定、测试入口和源码包清单同步更新。没有新增依赖或后台服务。
