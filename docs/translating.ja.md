# コミュニティ翻訳ガイド

中国語が原文です。英語も参考にできます。画面、ヘルプ、エラー、ランチャーの通知、PowerShell のダウンロードメッセージは `locales/` にまとめています。C++ の変更は不要です。翻訳はプログラムに同梱されるため、利用者が別の言語パックを入手する必要はありません。

## 既存の翻訳を修正する

1. `zh-CN.json`、`en-US.json`、`ja-JP.json` のいずれかを開きます。
2. `strings` 内の右側のテキストだけを編集します。左側のキーはコードから参照するため、名前を変えないでください。
3. UTF-8 で保存します。改行は `\n`、段落の区切りは `\n\n`、二重引用符は `\"`、バックスラッシュは `\\` と書きます。
4. `{path}`、`{version}` などの名前付きプレースホルダーを保持します。位置は変えられますが、翻訳や削除はしないでください。値はそのまま挿入され、翻訳の書式として再解釈されません。
5. プロジェクトのルートで次のコマンドを実行します。言語ファイルと、自動更新された `setup.ps1` を一緒に提出します。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/locales.ps1 -Generate
powershell -NoProfile -ExecutionPolicy Bypass -File tools/locales.ps1
```

検証に Visual Studio は不要です。`-Generate` は組み込みテキストを更新します。引数なしでは確認だけを行い、ファイルを変更しません。`work/LocalizationData.h` と `setup.ps1` の `BEGIN GENERATED LOCALES` 部分は手動で編集しないでください。

## 言語を追加する

1. `locales/zh-CN.json` をコピーします。例：`fr-FR.json`。
2. `locale` を `fr-FR` に、`nativeName` をその言語での名称（例：`Français`）に変更します。メニューに表示するため、短い名称にしてください。
3. `fontFamily` に、その言語に適した Windows 標準フォントを指定します。ラテン文字には `Segoe UI` が使えます。フォント名は最大 31 文字です。現在は左から右に読むレイアウトだけに対応しています。
4. `locales/languages.json` の `languages` 配列の末尾に `{"tag":"fr-FR","complete":false}` を追加します。中国語は先頭に残します。ファイル名、`locale`、`tag` を一致させてください。
5. `strings` を翻訳します。未翻訳のキーは削除するか、値を空にできます。その項目には中国語が使われます。すべて翻訳したら `complete` を `true` にすると、訳抜けがビルドエラーになります。
6. 上記のコマンドを実行します。新しい言語はメニュー、両方の EXE、PowerShell の文言、ソースアーカイブに自動で含まれます。画面言語の追加に C++ やリリース用ファイル一覧の変更は不要です。

組み込みの 3 言語は全項目の翻訳が必要です。新しい言語は部分的な翻訳から提出できます。検証では未翻訳の件数を表示します。エディターの入力補助には `locales/catalog.schema.json` を使えます。プロジェクトのスクリプトでは、キーの重複、不明なキー、プレースホルダー、文字とサイズの制限も確認します。

## 文言のルール

- 画面には短い文を使います。ボタンには操作名を、エラーには問題と次にすることを書きます。
- `setup.*` は設定ツール、`help.*` は ? のヘルプ、`error.*` は配置・入力エラー、`proxy.*` はポート検出、`startup.*` は自動起動の結果、`chain.*` は追加プログラムの通知、`download.*` は PowerShell 用です。
- ChatGPT、Codex、`.env`、HTTP、SOCKS5、PowerShell などの技術名はそのまま使います。
- `--proxy-server` などの引数、JSON フィールド、機械処理用のエラーコード、ファイル名、環境変数名、管理用マーカーは翻訳しません。プログラムやスクリプトが固定値として使います。
- 変数を含む文には名前付きプレースホルダーを使います。前後の断片を連結しないと意味が通じない文は避けてください。翻訳はプレーンテキストです。HTML や Markdown は使いません。ヘルプ内の改行はそのまま表示されます。
- Windows のダイアログボタンやシステムエラーの詳細は、Windows の言語で表示されることがあります。他社プログラムの名称やエラーは本プロジェクトでは翻訳しません。

## 実際の表示を確認する

Visual Studio の C++ デスクトップ開発ツールをインストールした後、ルートで実行します。

```powershell
cmd /c tests\test-build.cmd
cmd /c tests\analyze.cmd
```

`outputs/ChatGPTLauncherSetup.exe` を開き、右上で新しい言語を選びます。メイン画面、詳細設定、言語メニュー、? のヘルプ、ライト・ダークの両テーマを確認します。ウィンドウを小さくし、表示倍率 100%、125%、150%、175%、200% でも確認してください。ボタン、スイッチ、ヘルプアイコンが重ならず、空の入力欄のヒント、長いエラー、複数の結果をまとめたメッセージが切れていないことを確認します。

自動テストは隔離フォルダーとテスト用の代替処理を使います。実際の自動起動フォルダーへの配置や ChatGPT の終了は行いません。スクリーンショットは `work/` に保存します。個人のパスが写った画像をコミットしないでください。

機能を追加するときは中国語の原文を先に更新し、その後で英語、日本語、呼び出しコードを更新します。意味が変わらないキーは名前を保持します。意味を変える場合はすべての訳を見直します。使わなくなったキーは全言語から削除します。`schemaVersion` は言語ファイルの構造に互換性のない変更がある場合だけ上げます。

## 利用者向け文書を翻訳する

中国語は元のファイル名を使います。英語は `.en.md`、日本語は `.ja.md` を付けます。現在の対象はルートの `README`、`docs/translating`、`docs/taskbar-repair`、`docs/release-upload`、`assets/README` です。各文書の先頭に 3 言語へのリンクを置きます。

手順、制限、ボタン名、リンクを原文と揃えます。ボタン名は該当言語のカタログに合わせます。コマンド、引数、環境変数、ファイル名は変更しません。リンクは同じ言語の文書を優先し、未翻訳の開発者文書には「中国語」と明記します。リリースノートは GitHub Release の本文にコピーするため、先頭の言語リンクには完全な GitHub URL を使います。バージョン番号とダウンロード先も揃えてください。

`powershell -NoProfile -ExecutionPolicy Bypass -File tests/documentation-tests.ps1` で言語リンク、ローカルリンク、コマンド例を確認します。文書の翻訳を追加するときは、そのテストの文書グループと言語サフィックスを更新し、`tools/release-sources.ps1` のソース一覧にファイルを追加します。画面の言語を追加するだけなら、全文書の翻訳は不要です。`AGENTS.md`、`HANDOFF.md` などの内部作業記録は翻訳しません。
