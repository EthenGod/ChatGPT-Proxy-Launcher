# 更新后的任务栏图标修复

目标：已确认开始菜单快捷方式残留旧版本路径时，让启动器在启动前自动修复，避免每次应用更新后手工处理。

方案：仅检查当前用户 Programs 文件夹内的 `ChatGPT.lnk`。要求应用标识为 `com.openai.codex`，目标是当前启动器自身，或同一安装根目录下、身份符合正式应用包的 `app\ChatGPT.exe`。将目标、图标和工作目录固定到当前启动器，原有参数与应用标识保留。修复采用系统 Shell Link 接口，不手工解析二进制快捷方式。

正常路径只读检查，不重复保存；缺失或无法确认身份时不接管、不新建。`--launcher-check` 不执行修复。快捷方式参数不会被本次调用的临时参数覆盖，代理仍由调用方传入。首次修复的原件备份至当前用户本地应用数据目录的 `ChatGPTProxyLauncher/TaskbarShortcut.original.lnk`，以后不覆盖备份。

保存前生成单个临时文件并回读验证，再原子替换快捷方式，只通知该文件的 Shell 更新，不清全局图标缓存、不重启资源管理器。准备期间持有只读文件锁；提交时需要释放锁并重命名，因此仍存在很窄的并发编辑窗口。任何修复失败均不阻止正常启动，不增加常驻程序或日志。

边界：不扫描任务栏固定项、不修改系统自启和官方包文件。超过经典 Shell 路径长度、重定向到网络的 Programs、其他应用标识、自定义目标或迁移后不再指向当前启动器的快捷方式均跳过。官方改变文件名、身份或图标机制仍可能需要调整。固定路径的启动器必须保留。

验证：`work/test-build.cmd` 增加隔离快捷方式测试，覆盖旧包更新、重复调用、身份排除、参数及属性保留、首次备份、备份和提交失败、文件占用、损坏文件、路径边界；所有链接都在 `work/`，Shell 通知替换为测试桩。入口测试确认检查模式不触发修复，正常启动仍原样传参。实际商店更新和任务栏显示仍需真实使用验证。
