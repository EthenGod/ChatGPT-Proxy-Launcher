# 内存和线程安全审查

## 目标与范围

检查启动器、配置器工作线程、系统资源释放和扩展调度。只修复有明确触发条件的问题。保持原生程序、参数传递和现有界面行为。测试使用隔离目录，不更改已部署程序或真实自启配置。

## 问题与处理

- 保存结果原来随窗口消息转交裸指针。窗口销毁后未处理消息，会丢失结果的释放责任。现在由配置器持有结果，消息只通知完成。工作线程写完后发布原子完成状态；界面先等待线程结束，再读取。窗口销毁前回收工作线程和结果。
- 保存或端口检测的完成消息投递失败，会让界面一直停在执行中。现在执行期间共用一个 100 毫秒兜底计时器。空闲时停表。创建计时器失败时不开始新任务。
- 多处系统字符串、命令行参数和文件选择器对象，在后续字符串复制抛出异常时会漏释放。现在先交给作用域对象管理，再执行可能分配内存的操作。
- 扩展调度和后台配置入口，在异常保护范围外构造了需要分配内存的对象。扩展错误报告也可能再次分配失败。现在由最外层返回错误码。普通启动保留 ChatGPT 已启动的结果；显式扩展调用无法生成报告时返回 70。后台配置命令对象构造失败返回 50。
- 创建临时文件前先预留路径空间。扩展清理路径提前生成，析构时不再拼接字符串。
- 子进程环境块一次预留空间，再逐段写入，减少临时字符串和扩容。补上空环境块的第二个结束符，保留大小写覆盖、驱动器变量和 Unicode 内容。

## 边界

异步工作不强行取消。窗口关闭需要等正在执行的本地操作结束。Windows 文件系统或第三方组件长期不返回的情况，不能靠强杀线程安全解决。测试不证明真实登录自启、网络连接或应用退出行为。

旧附加程序入口会短暂修改当前进程的环境变量，当前只在启动器主线程顺序执行。它不承诺支持多线程并行调用。以后若改为并行启动，须先改成独立的子进程环境块。

本次只生成 `outputs/` 中的两个程序，未替换已安装版本，未发布 Release。
