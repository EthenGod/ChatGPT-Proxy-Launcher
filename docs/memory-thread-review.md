# 内存和线程安全审查

## refactor/ui 配置器和启动器

对照版本为 `0560daf`。检查了新配置器的任务队列和关闭流程、Rust/C++ 返回值的释放、原生兼容窗口的工作线程、部署回滚及两个 EXE 的内嵌资源。

- 原先每个原生请求先占一个阻塞线程，再争用同一把锁。现在请求先异步排队，轮到它时才使用工作线程。GUI 使用两个调度线程。命令行和原生兼容入口在创建调度器前分流。[Tokio 调度线程设置](https://docs.rs/tokio/latest/tokio/runtime/struct.Builder.html#method.worker_threads)
- 原先同时到达的关闭请求可能重复获得许可。现在关闭和接收任务共用一把短锁。前端取消等待时，尚未派发的任务可以撤销，已经进入 C++ 的任务继续持有许可直到返回。工作线程异常后保留“提交状态未知”，后续任务仍能执行。
- 原先检查启动器时会读取整份文件。现在用 8 KiB 缓冲分块核对。只有要替换内容不同的受管文件时才保留完整回滚副本。测试覆盖最后一块的单字节差异、后续写入失败，以及替换后文件内容损坏。两种失败都能恢复原文件。
- 独立启动器只内嵌扩展通知和通用文案。配置器继续携带完整原生文案，内嵌同次构建的启动器。Rust 发布构建使用尺寸优化，保留异常展开。[Cargo 发布配置](https://doc.rust-lang.org/cargo/reference/profiles.html#opt-level)

两个 EXE 均取正式构建。部署测试使用 4 MiB 加 37 字节的合成启动器，并对当前线程的 C++ 堆分配求和。计数不含测试文件本身、Windows 或 COM 在内部分配的内存。

宿主私有内存的五次范围从 6.16–6.30 MiB 降至 4.21–5.06 MiB。整棵进程树的范围分别为 185.57–199.65 和 190.81–199.21 MiB，有明显重叠。两组首轮空闲期间均只读取一次配置，每轮关闭后所属进程全部退出。此次观测限于短时窗口使用。

真实 WebView2 隔离窗口中，保存延迟 5 秒，期间同时提交 24 个只读请求。原生关闭命令返回忙碌，点击标题栏关闭也被拦住。保存前、排队时和任务完成后，宿主都是 14 个线程。全部请求返回，隔离设置快捷方式写入成功，第二次关闭后所属进程全部退出。

原生测试覆盖 56 个系统缓冲区分配故障点，结束时跟踪到的缓冲区全部释放。C ABI 和扩展调度各覆盖 128 个分配故障点。旧界面在保存和端口检测同时运行时关闭窗口，也通过了线程回收检查。旧附加程序入口仍会暂时修改进程环境，须保持单线程顺序调用。

`tests/analyze.cmd` 和 `tests/test-build.cmd` 通过，包含 MSVC 静态分析、Clippy、68 项前端测试和 10 项 Rust 测试。8 组后台命令结果与原生版一致。显式兼容模式和模拟缺失 WebView2 时均只启动一个进程。两个本地 EXE 已核对同次构建的内嵌载荷。

## v1.1.2 发布前复查

基线为 `7cd0a98`。检查工作线程结果交接、销毁顺序、COM 和系统句柄、链式启动的临时内存。保持现有协议和功能，不增加并行任务。

- 保存与端口检测由各自工作线程写结果，原子完成标记发布后，界面先 `join` 再读取。关闭窗口先等线程结束，再释放窗口和结果。共享文本表只读，语言索引用原子变量。
- 重点优化子进程创建后的资源寿命。命令行、环境块和属性列表只需活到 `CreateProcessW` 返回；进程与 Job 句柄仍须保留到就绪检查完成。
- 增加隔离测试，在第一次进程等待前核对环境块已释放、初始线程句柄已关闭。保留创建失败、残留子进程、安全重试和低内存测试。
- 版本、三种语言的发布说明、完整测试、静态分析与四个 Release 附件一并验收。不用本机 ChatGPT 或已部署配置作测试目标。

### 验证结果

- 全部 20 个正式 C++ 源文件通过 `/W4 /WX /analyze`。Windows PowerShell 5.1 与 PowerShell 7 的文档、下载、后台入口和回执示例检查通过。

测试中的释放观察器用 [_msize](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/msize) 查询 `malloc` 分配块范围，避免把 MSVC 大容器内部对齐的数据指针误当成分配起点。此观察器不进入正式程序。

## 目标与范围

检查启动器、配置器工作线程、系统资源释放和扩展调度。只修复有明确触发条件的问题。保持原生程序、参数传递和现有界面行为。测试使用隔离目录，不更改已部署程序或真实自启配置。

## 问题与处理

- 保存结果原来随窗口消息转交裸指针。窗口销毁后未处理消息，会丢失结果的释放责任。现在由配置器持有结果，消息只通知完成。工作线程写完后发布原子完成状态；界面先等待线程结束，再读取。窗口销毁前回收工作线程和结果。
- 保存或端口检测的完成消息投递失败，会让界面一直停在执行中。现在执行期间共用一个 100 毫秒兜底计时器。空闲时停表。创建计时器失败时不开始新任务。
- 多处系统字符串、命令行参数和文件选择器对象，在后续字符串复制抛出异常时会漏释放。现在先交给作用域对象管理，再执行可能分配内存的操作。
- 扩展调度和后台配置入口，在异常保护范围外构造了需要分配内存的对象。扩展错误报告也可能再次分配失败。现在由最外层返回错误码。普通启动保留 ChatGPT 已启动的结果；显式扩展调用无法生成报告时返回 70。后台配置命令对象构造失败返回 50。
- 创建临时文件前先预留路径空间。扩展清理路径提前生成，析构时不再拼接字符串。
- 子进程环境块一次预留空间，再逐段写入，减少临时字符串和扩容。补上空环境块的第二个结束符，保留大小写覆盖、驱动器变量和 Unicode 内容。

## 边界

异步工作不强行取消。窗口关闭需要等正在执行的本地操作结束。Windows 文件系统或第三方组件长期不返回的情况，不能靠强杀线程安全解决。测试不证明真实登录自启、网络连接或应用退出行为。

旧附加程序入口会短暂修改当前进程的环境变量，当前只在启动器主线程顺序执行。它不承诺支持多线程并行调用。以后若改为并行启动，须先改成独立的子进程环境块。

本次只生成 `outputs/` 中的两个程序，未替换已安装版本，未发布 Release。
