# 自动化接口复审

日期：2026-11-14。基线：`eebabbb`。范围：后台部署、发现查询、注册、回执和重试。版本保持 v1.0.7 开发版，不改 Release。

## 目标

修复可复现的边界问题。集中协议版本、能力及限制。让坏配置可以停用或按 ID 移除。给开发者一个简短入口，详细字段继续保留在规范中。

## 修复结果

| 原问题 | 现在的处理 |
| --- | --- |
| 作者清单损坏后，停用也被清单校验挡住 | 停用只验证注册归属与新覆盖项；重新启用必须完整校验 |
| 注册目录超过 32 项，按 ID 移除也失败 | 停用与移除可单独读取指定记录；无法检查全目录时返回警告，不跳过目标归属校验 |
| 两个 EXE 各自判断部署状态，校验范围不同 | 共用发现模块；检查能力列表、版本列表、路径和数值版本，不将两个空版本视为有效 |
| 配置器查询依赖私人参数和自启快捷方式 | 改为只读管理快捷方式及发现信息；区分文件缺失、记录损坏和读取失败 |
| 无效失败回执在校验完成前改写错误码和重试标志 | 纯解析函数校验整份回执，再交给运行逻辑；坏回执不会污染本次状态 |
| Windows 保留设备名漏掉上标数字 | 原生与 PowerShell 同时拒绝 COM¹/²/³、LPT¹/²/³ 及扩展名变体 |
| PowerShell 辅助函数在严格模式下访问缺失字段，写失败可能留临时文件 | 明确处理无回执的短任务上下文；失败只清理本次新建的临时文件 |

Windows 设备名规则见 [Microsoft 文件命名说明](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)。

## 维护方式

公共版本、能力和限制集中在 `AutomationContract.h`。发现信息由 `DeploymentDiscovery` 统一生成与读取。回执语法归 `CompanionProtocol`，进程身份、等待与重试仍归 `CompanionRunner`。没有新增运行库或常驻进程。

开发者从[接入指南](developer-guide.md)开始。详细命令和字段继续留在原规范中。补充配置请求、全链策略、回执 Schema 及配置示例；契约测试检查它们与代码中的版本、能力和限制一致。Schema 不能代替运行时语义检查。

停用项不读取作者清单，既能恢复损坏配置，也减少无用读文件。普通空目录仍走原有快速返回；等待仍使用系统事件，重试次数、单次时间和全链时间均有上限。

## 验证

- `cmd /c tests\test-build.cmd`：构建和全套隔离测试通过。新增覆盖损坏清单停用、超限恢复、拒绝删除无归属记录、无效回执、发现信息损坏和文件独占锁。
- `cmd /c tests\analyze.cmd`：正式源码静态分析通过。
- 后台下载及回执辅助函数在 Windows PowerShell 5.1、PowerShell 7 通过；辅助函数测试启用严格模式。
- Schema 示例和三种回执结构通过开发期校验；跨状态多余字段被拒绝。标准测试中的契约检查不依赖额外 Schema 引擎。
- `work\chain-tests.exe "%CD%\work" --benchmark`：空目录及 30 秒等待检查通过，未增加句柄，没有强杀测试子进程。具体采样留在忽略的 `work/`，不作为其他机器的性能保证。
- 源码发布清单包含新增模块、文档和测试。检查忽略规则及 `git diff --check`；未生成或上传 Release。

## 边界

扩展是当前用户主动信任的本机程序。管理标记、文件 token 和 Job 不是权限隔离机制。文件检查用于拒绝常见误配和冲突，不承诺阻止同权限恶意进程的并发修改。

不关闭真实应用，不改真实部署或自启。验收使用隔离文件、测试子进程和系统调用替身。静态分析及编译通过不能代替第三方插件实机验证。
