# 项目审查与性能优化

这里记录启动器、配置器和共用代码的性能对照。桌面配置器的进程树、启动和包体基线见[界面重构验证](ui-refactor.md#第-4-阶段默认入口与交付验证)。

## 2026-11-19 参数预览与 JSON 读写

对照版本为 `50554bb`。参数预览现在直接读取普通参数的原文。包含双引号的参数仍由 Windows 解码，空参数和转义引号沿用原规则。校验输入时无需查询用户目录或初始化 COM。保存仍走原有路径检查、写锁和回滚。

JSON 解析器先检查 UTF-8，再在自己的 UTF-16 缓冲区中还原转义。调用方的输入保持原样。编码器预留输出空间，一次复制开头的普通文本。Unicode 转义仍会核对代理对。Rust 直接序列化设置对象，读取状态和保存共用同一处返回值检查。前端队列只等待命令完成，页面自行管理返回的数据。

同一用例使用相同测试代码和 MSVC `/O1 /MT` 构建选项。新旧程序固定在同一逻辑处理器，交替运行 5 轮。每轮先预热 20 次，再计时并逐次核对结果。表中耗时取 5 轮单次平均耗时的中位数。字节数统计 C++ 堆分配的累计请求量。

| 合成输入 | 每轮次数 | 耗时，微秒（beta.2 → 本次） | 单次分配次数 | 单次累计申请字节 |
| --- | ---: | ---: | ---: | ---: |
| 预览代理、绕过地址、空参数和带空格的中文参数 | 3000 | 1.55 → 0.99 | 27 → 16 | 2804 → 1956 |
| 同一组输入再加 96 个普通参数 | 3000 | 26.73 → 5.95 | 515 → 24 | 61154 → 32419 |
| 读写含 Windows 路径和带引号参数的小型 JSON 配置 | 10000 | 1.25 → 1.13 | 33 → 29 | 3902 → 3706 |
| 读写含 24000 个 ASCII 字符、中文、转义和表情的 JSON | 1500 | 149.12 → 91.13 | 72 → 35 | 523755 → 244881 |
| 读写重复 300 组制表符、反斜杠、引号、表情和 Unicode 转义的 JSON | 2000 | 12.63 → 11.28 | 32 → 7 | 55288 → 34606 |
| 读写开头含转义、后接 24000 个普通字符的 JSON 路径 | 500 | 125.27 → 76.58 | 44 → 5 | 519371 → 168364 |

附加程序另测 3 轮。每轮预热一次，测量 5 次，并核对隔离子进程收到的配置和参数。准备一份 24 KB 配置，堆分配从 512 次降至 457 次，申请量从 705960 字节降至约 430550 字节。准备时间包括本地文件读写，截止于创建子进程前。两版各轮的中位数分别为 4.26–4.89 ms 和 4.17–4.88 ms，本次未测出稳定的整体提速。

兼容性另用 10000 组 Windows 参数和 10000 组 JSON 输入与 beta.2 对照。参数导入结果和错误码一致。JSON 接受 6944 组，拒绝 3056 组，输出字节和错误原因均一致。隔离桥接测试还覆盖系统目录不可用、调用线程已进入多线程 COM 模型的情况。

真实 WebView2 隔离窗口连续打开并关闭 3 次，所属进程每次均退出。三次的进程树工作集为 382.96–386.43 MiB，私有内存为 191.62–198.66 MiB。首轮空闲 60 秒，配置只读取一次。该记录用于检查窗口生命周期，未测量实际 ChatGPT 启动耗时。

完整回归后可运行 `work\memory-tests.exe` 复核长参数、长 JSON 和密集转义的分配上限。运行 `work\chain-tests.exe "$PWD\work" --benchmark-context` 可复测附加程序的准备开销。

## 目标与边界

- 减少配置器的重复进程扫描、文本复制和局部绘制开销。
- 减少启动器创建进程时的临时分配。保留启动后退出，不增加常驻进程或跨次缓存。
- 保留代理识别条件、参数原样传递、文件校验、冲突保护及保存失败回滚。
- 统一构建环境入口和文件格式约定。内部记录放在此处，README 继续面向用户。
- 不更改真实用户配置，不关闭真实 ChatGPT，不清理已有备份或重打旧 Release。

## 检查与验证

- 基线为 `8692fb2`。先运行完整隔离测试，再比较同一组合成数据的耗时。
- 代理检测检查扫描次数、同次缓存边界、配置解析结果及异常输入。
- 启动器检查分配次数、路径、工作目录、引号与参数边界。进程创建只使用隔离测试子进程。
- 界面检查局部重绘、滚动、主题、缩放、按钮键盘行为和空闲计时器。
- 最后运行完整构建、隔离测试和静态分析。统计与本机原始报告保存在 `work/`。

## 风险

- 缓存仅在一次检测内有效。下次点击须重新读取，避免代理工具重启后沿用旧 PID。
- 减少绘制不能漏掉圆角边缘，也不能恢复原生按钮绘制。完整绘制与局部绘制应得到相同图像。
- 合成测试不代表真实应用启动、网络连接或第三方代理的端到端速度。

## 实施结果

审查日期：2026-11-11。对照提交 `8692fb2`。版本号和旧 Release 保持原样。

| 环节 | 原实现 | 本次处理 |
| --- | --- | --- |
| 代理进程发现 | 按工具名重复获取进程快照，完整检测路径为 10–11 次 | 每次检测最多获取一次；同一进程的路径查询也只做一次 |
| 代理配置解析 | 复制整份 YAML，再逐行创建和裁剪字符串 | 使用 `string_view` 读取原文本；保留重复键、多文档和非法端口的拒绝规则 |
| v2rayN 配置发现 | 安装根目录与本地配置目录相同时可能读取两遍 | 合并相同目录；没有可核对的监听端口时跳过配置读取 |
| 快捷方式读取 | 同时保留三个 32768 字符缓冲区和一个 1024 字符缓冲区 | 复用一个缓冲区，临时缓冲区总容量从 194 KiB 降到 64 KiB |
| 启动进程 | 分别分配命令行和工作目录缓冲区 | 合并为一次分配；已有工作目录时不再复制目录 |
| 界面刷新 | 小范围刷新也申请整个客户区的缓冲区 | 按 `rcPaint` 申请；完全位于裁剪区域外的圆角不再构造绘图对象 |

代理检测的文件、快照和进程句柄改为作用域内自动释放，避免内存分配异常时遗漏关闭。未引入后台服务、持久缓存、日志或第三方运行库。

项目规范新增 `.editorconfig` 和 `.gitattributes`，约定编码、缩进及换行，不进行全项目重排。`tools/msvc-env.cmd` 统一定位 C++ 工具链。`tests/analyze.cmd` 提供独立的静态分析入口。发布源码清单已同步，51 个文件齐全且无重复；构建产物、本机数据和旧 Release 不进入源码包。

## 测量与验收

- YAML：4194227 字节的合成配置，每轮解析 20 次。新旧程序使用相同的 MSVC `/O1 /MT` 选项，交替测量 5 轮。单次解析耗时中位数由 **37.245 ms 降至 2.821 ms**，约减少 92%。旧版范围 34.692–37.911 ms，新版范围 2.436–3.388 ms。数据仅包含虚构节点。
- 上述数值只衡量 YAML 解析，不包括磁盘读取、进程查询、网络或 ChatGPT 启动。缓冲区容量也不等于整个程序的内存占用。
- 滚动：用同一版隔离界面测试交替运行新旧绘制代码，每轮滚动 301 次，共 3 轮。旧版 1838–1913 ms，新版 1909–1933 ms，中位数为 1881/1914 ms。未确认整体滚动提速；保留此结果，不把局部缓冲区优化当作帧率提升。
- 三张基线图像逐像素一致：深色 150%、代理选项展开后的 200% 窄窗口、短窗口滚动状态。新增分块与完整绘制对比，覆盖浅色、深色、高对比度、100–200% 缩放和滚动；全部一致。
- 完整构建与隔离测试通过。覆盖原样传参、随机参数、分配失败、附加程序、任务栏链接、部署回滚、`.env` 合并、自启状态、应用退出替身、下载与清理、按钮键盘行为。补充的局部绘制测试单独复测通过。下载测试在 Windows PowerShell 5.1 和 PowerShell 7 中均通过。
- 8 个正式 C++ 源文件通过 `/W4 /WX /analyze` 静态分析，退出码为 0。
- 检查源码清单、忽略规则、差异空白和常见敏感信息标记。v1.0.5、v1.0.6 的原有附件通过各自 SHA-256 清单核对。保留 `work/` 中的备份，不批量删除。

## 2026-11-16 路径与部署内存优化

基线为 `1fb4fc8`。`FullPath` 原来每次分配 32768 个宽字符，再为路径组件创建临时字符串。它会被部署、注册读取和链式启动的路径检查重复调用。

现在先用 260 个宽字符的栈缓冲区。超出后按 Windows 返回的容量分配，仍限制最大长度。路径组件使用 `wstring_view`，逐级文件属性检查复用原缓冲区。部署预检和写入直接读取内嵌 EXE 的字节，不再建立另一份完整副本。

对照采用相同 MSVC `/O1 /MT` 配置。使用带空格、中文和 `..` 的合成绝对路径，不访问真实文件。每轮预热 1000 次，再测 20000 次；新旧函数交替运行 5 轮。

| 单次路径规范化 | 基线 | 优化后 |
| --- | --- | --- |
| C++ 堆分配次数 | 5 | 1 |
| 请求分配字节总数 | 65751 | 96 |
| 耗时中位数 | 1.150 微秒 | 0.167 微秒 |
| 五轮耗时范围 | 1.031–1.204 微秒 | 0.157–0.186 微秒 |

这次测量的函数耗时约减少 85.5%。分配字节是测试替身记录的 `operator new` 请求量，不是整个应用的内存占用。它也不能代表 ChatGPT 启动或磁盘读写提速。

`tests/memory-tests.cpp` 保留分配上限检查和长短路径边界检查。`tests/setup-tests.cpp` 保留异常回滚和路径预检回归。原始对照程序和输出留在被忽略的 `work/`。

链式启动另做一次现有基准复测。空目录分派 200 次，中位数为 0.0410 毫秒，95 分位为 0.0462 毫秒，句柄数量不变。两次内存快照之间私有提交量增加 8 KiB；该测量包含首次调用的初始化，不能用它断言持续增长或泄漏。30 秒等待用例在 30016 毫秒后返回，进程计时精度内未记录到父进程 CPU 时间，测试子进程随后自行退出。此结果不代表真实插件表现。

## 2026-11-16 链式上下文与文件移除

基线为 `61dc62b`。上下文改用移动操作接收局部 JSON 对象，参数数组预留容量。上下文树和序列化字节在创建子进程前释放，不再留到就绪等待结束。随机令牌预留固定容量，避免扩容。

使用相同测试程序与 MSVC `/O1 /MT`，只替换 `CompanionRunner.cpp`。新旧程序交替运行 3 轮，使用相同可执行文件路径和合成环境。每轮预热一次，再测 5 次。输入为 24000 个 ASCII 字符的配置，加空参数、中文、空格和引号；同时核对测试子进程收到的数据。

| 创建子进程前的准备阶段 | 基线 | 优化后 |
| --- | --- | --- |
| C++ 堆分配次数 | 576 | 510 |
| 请求分配字节总数 | 757969 | 702354 |
| 各轮耗时中位数范围 | 4.482–4.947 ms | 4.347–4.910 ms |

分配次数减少约 11.5%，累计请求字节减少约 7.3%。统计包含注册读取、上下文写入及子进程环境准备，不包含进程创建。请求字节不是峰值内存；耗时包含本地文件读写且区间重叠，不宣称启动速度明显提升。

快捷方式及注册项共用 `RemoveUnchangedFile`，按 4 KiB 分块核对。1 MiB 加 3 字节的测试文件只触发 160 字节的 C++ 分配，来自路径检查；不再为比较另建完整文件副本。测试还确认核对期间无法写入或重命名目标，句柄数量不变。

空目录调度复测 200 次，中位数 0.0294 ms，95 分位 0.0331 ms，句柄数量不变。私有提交量两次快照相差 12 KiB，包含初始化和容器容量，不据此判定泄漏或整个程序的固定占用。30 秒等待在 30000 ms 后返回，进程计时精度内父进程 CPU 时间为 0，子进程随后自行退出，没有强杀。
