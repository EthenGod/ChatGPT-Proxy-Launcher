# 后台部署与链式启动实现审查

日期：2026-11-14。基线：`4f1d596`。开发版本：v1.0.7。未生成或上传 Release。

## 目标与范围

- 外部脚本通过参数完成部署，取得可判断的结果。后台模式不打开界面或抢焦点。
- 插件用固定 ID 和版本清单描述入口、参数及依赖。初始化完成后报告就绪。
- 失败时只做有条件、有次数和时间上限的重试。启动器结束后不常驻。
- 保留现有 GUI、普通启动目录、原样传参、文件所有权和回滚规则。

## 审查后修正的逻辑

| 问题 | 处理 |
| --- | --- |
| 旧 EXE 不认识后台参数，仍会打开 GUI | PowerShell 先读取版本资源，低于 1.0.7 则停止 |
| GUI 与脚本可能同时改写部署 | 共用本用户操作锁；锁内重新读取状态，最多等待 5 秒 |
| 后续自启处理失败可能被当成没有部署 | 文件提交结果与后续动作分开；保留 `committed` |
| 旧参数解析失败后沿用半份配置 | 后台的 `preserve` 拒绝无效旧参数；可显式使用 `defaults` |
| 结果路径可能污染已有配置 | 只创建新 `.json` 文件，保护请求、清单、发现、策略及注册路径 |
| 发现信息与实际部署可能脱节 | `discovery.json` 纳入文件提交、回读和回滚 |
| 父进程退出后仍有子进程，重试会重复启动 | 创建进程时附加 Job；确认整个进程族退出后才重试 |
| 进程退出事件早于 Job 计数更新 | 在本次截止时间内等待计数归零，不立即误报失败 |
| Job 属性指向短寿命局部变量 | Job 句柄存储保留到 `CreateProcessW` 返回 |
| 上一次尝试的回执可能误认成本次就绪 | 每次使用新目录、尝试 ID 和 256 位随机 token |
| 注册后又添加相同旧入口，重复启动 | 跳过可明确识别的旧入口，并报告冲突 |
| 小数经浮点转换后误当成协议整数 | JSON 整数按十进制精确校验 |

## 实现选择

GUI 与后台入口共用 `SetupCore` 的预检、所有权和提交逻辑。命令合并与动作选择放在 `SetupCommandLine`。没有新增另一套部署服务或常驻进程。

JSON 使用独立的小型原生解析器。输入最多 64 KiB、16 层。它直接拒绝重复键、非法 UTF-8、未配对代理项和 NUL。Schema 用于开发期检查，不能代替运行时的路径和配置关系检查。

注册文件与作者清单分开。升级同一清单时保留用户覆盖项。删除注册只删除指定 ID 的记录。规范入口与旧快捷方式入口保持不同的参数规则，BAT/CMD 参数只通过上下文传入。

等待使用进程句柄及目录变化通知。只有根进程已退出、仍需确认进程族时，才以不高于每 250 ms 的频率复查 Job 计数。没有全系统进程轮询。

## 验证

`tests/test-build.cmd` 构建两个正式 EXE，并运行以下隔离测试：

- 既有启动器、500 组随机参数、旧附加程序、任务栏快捷方式、部署、代理发现、自启、应用退出替身和 GUI 回归。
- 后台 JSON 校验、`plan` 无部署写入、真实隔离快捷方式、`.env` 合并、发现状态、所有权冲突、用户锁、参数错误退出。
- 文件提交及回滚故障注入，包括发现文件最后提交失败、`.env` 恢复和回滚不完整。
- 扩展就绪、立即退出、现有实例身份、短任务、真实残留子进程、错误 token、迟到回执、新 token 重试、永久失败。
- Job 创建失败和状态读取失败注入、依赖环与停用、缺依赖、总预算耗尽、并发链跳过、旧目录重复入口。
- 注册来源迁移、覆盖项保留、指定 ID 移除、未知文件保护；批处理特殊文件名和参数注入拒绝。
- PowerShell 版本与校验门槛、结构化结果、会话保留、清理和结果保护；回执辅助函数的原子写入及过期拒绝。

PowerShell 下载与回执示例测试同时在 Windows PowerShell 5.1 和 PowerShell 7 中运行。下载、浏览器、自启和应用退出操作使用替身。新失败提示验证了 10 秒关闭回调，未确认实际桌面的显示效果。

完整构建和回归脚本通过。`tests/analyze.cmd` 的全部 17 个正式 C++ 源文件通过 `/W4 /WX /analyze`。源码清单的 82 项均存在且无重复，覆盖全部正式模块、文档和测试。忽略规则与差异空白检查通过。

## 性能测量

以下为本轮本机隔离测量，只表示该次样本。原始输出保留在忽略目录 `work/`，不进入源码包。

| 场景 | 结果 | 边界 |
| --- | --- | --- |
| 不存在的启动目录，预热后各 200 次 | 旧派发 p50/p95 为 0.0153/0.0246 ms；新调度为 0.0294/0.0399 ms | 同一进程内调用，不含 EXE 加载和 Known Folder 查询 |
| 上述空目录循环 | 私有提交与峰值提交增量均为 0 字节；句柄数不变 | 已预热分配器，不代表完整程序峰值 |
| 30 秒无回执 | 实际等待 30016 ms；记录到的父进程 CPU 增量为 0 ms | 低于 Windows 该计时精度，不表示没有执行任何指令；子进程随后自行退出 |
| 新旧 EXE 交替各 100 次只读检查 | p50 为 13.9623/14.9876 ms；p95 为 15.4703/16.7716 ms | 使用 `--launcher-check`，该测试上下文均返回 1168，走未找到包的只读错误路径 |
| 上述 EXE 测量的采样峰值提交 | 最大值分别为 1134592/1318912 字节 | 约增加 180 KiB；1 ms 采样可能漏掉更短峰值 |

这些结果没有显示明显的空路径回退或忙等。但完整 ChatGPT 启动链、冷磁盘和真实插件仍未做同机端到端对照。设计中的 p50/p95 与 1 MiB 门槛不能只靠错误路径样本宣布全部达到。

复测命令：

```cmd

```
