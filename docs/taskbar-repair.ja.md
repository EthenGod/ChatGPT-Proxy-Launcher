# 更新後のタスクバーアイコンの修復

スタートメニューのショートカットに古いバージョンのパスが残っていることを確認できた場合、ランチャーが ChatGPT の起動前に修復します。アプリの更新後に毎回手動で修復する手間を減らすための機能です。

確認するのは、現在のユーザーの Programs フォルダーにある `ChatGPT.lnk` だけです。アプリ ID が `com.openai.codex` であり、リンク先が現在のランチャー自身、または同じインストール先のルートにある正式パッケージの `app\ChatGPT.exe` である必要があります。リンク先、アイコン、作業フォルダーを現在のランチャーに合わせ、既存の引数とアプリ ID は保持します。修復には Windows の Shell Link API を使い、ショートカットのバイナリを直接解析しません。

すでに正しいショートカットは読み取るだけで、保存し直しません。存在しない場合や識別できない場合は、新規作成も管理の引き継ぎも行いません。`--launcher-check` では修復を実行しません。今回の呼び出しで指定した一時的な引数が、ショートカットに保存済みの引数を上書きすることはありません。プロキシ引数は引き続き呼び出し側が指定します。初回修復時の元ファイルは、現在のユーザーのローカルアプリデータ内の `ChatGPTProxyLauncher/TaskbarShortcut.original.lnk` にバックアップします。以後、このバックアップは上書きしません。

保存前に一時ファイルを 1 つ作成し、読み戻して検証します。その後、ショートカットを不可分に置き換え、そのファイルについてだけ Shell に更新を通知します。システム全体のアイコンキャッシュの削除や、エクスプローラーの再起動は行いません。準備中は読み取りロックを保持しますが、最後の名前変更にはロックの解除が必要なため、同時編集が入り込む短い時間は残ります。修復に失敗しても通常の起動は妨げません。常駐プログラムやログも追加しません。

対象外：タスクバーにピン留めした項目の検索、Windows の自動起動設定や公式パッケージの変更は行いません。従来の Shell のパス長制限を超えるパス、ネットワークにリダイレクトされた Programs フォルダー、別のアプリ ID、独自のリンク先、移動後に現在のランチャーを指さなくなったショートカットは処理しません。公式アプリのファイル名、識別情報、アイコンの仕組みが変わった場合は、この修復機能も調整が必要になることがあります。ランチャーは設定した場所に残してください。

検証：`tests/test-build.cmd` は隔離したショートカットでテストします。古いパッケージのパス、繰り返し実行、識別情報による除外、引数と属性の保持、初回バックアップ、バックアップや置換の失敗、使用中・破損したファイル、パス長の境界を確認します。リンクはすべて `work/` 内に置き、Shell 通知はテスト用に置き換えます。起動処理のテストでは、確認モードが修復を行わず、通常起動が引数をそのまま渡すことも確認します。実際の Store 更新とタスクバーの表示は、実利用での確認が必要です。
